# 业务口径评审采纳规则 v2

生效日期：2026-10-19。依据：用户明确要求“除了你判断需要人工复核的内容之外，相信AI审核的正确性”。适用于本项目后续业务口径评审，也用于采纳已有v2 AI预审中的明确结论。

## 默认处理

| 审核状态 | 采纳方式 | 是否需要用户逐题确认 |
|---|---|---|
| AI明确通过，有相应SQL/规则证据 | 直接记为通过 | 否 |
| AI明确失败，有相应SQL/规则证据 | 直接记为失败 | 否 |
| 按既定规则自动判定的执行失败 | 继续计失败，保留固定分母 | 否 |
| 明确标记待人工裁定 | 保持未决，列出具体规则、证据和待决问题 | 是 |

不能仅因判断来自AI而要求人工确认。已有预审文件的human_adjudication_required等通用“全部复核”提示，由本规则取代；明确的needs_human_adjudication状态仍有效。历史报告保留当时的审核流程记录。

## 哪些情况转人工

只在AI无法可靠完成判定时转人工，例如：冻结规则存在歧义或冲突；执行证据缺失、矛盾或哈希不匹配；SQL语义等价性或反例适用范围不能确定。必须说明具体哪一项不能确定，不能笼统要求全部复核。

## 记录和计算

- 明确保留decision_origin=ai_audit或execution_policy；不得写成human_verified。
- 每项可追溯到审核记录、实际执行SQL/capture哈希及逐规则证据。
- 本规则只改变审核结论的采纳权限，不改变业务定义、题目组成、必要规则、样本分母或数值容差。
- 全部未决项解决后，才输出完整口径正确率；有未决项时输出已通过、已失败、待裁定数量，不能从分母中删除未决项。
- 原始执行、预测、冻结评分器及历史验收不覆盖。新策略生成独立的policy-accepted记录，后续结果注明“AI审核采纳，人工处理例外项”。旧human-only评分器继续保留作为原版工具，不能通过伪造人工身份来绕过它。
